# モンスター仕様書テンプレート（ドラフト）

> 新規モンスターを実装する前にユーザーが作成する「内容仕様書」のテンプレート。`ai_docs/monster/create_new/new_monster_creation_guide.md` の実装手順はこの仕様書を一次情報源として進める。
> `monster_datapack_spec.md` が「データパックの技術的な構造仕様」であるのに対し、こちらは「このモンスターが具体的に何をするか」という**ゲームデザイン内容**を記述する。
> コピーして `ai_docs/monster/<name>/spec.md` として使う。
>
> **なぜこの仕様書が必要か**: `animated_java_<name>/`（AJエクスポート成果物）はコンテキスト圧迫のため Claude が Read/Grep しない運用になっている。移行作業では旧形式コードから frame 番号やロケータ名を読み取れたが、新規モンスターには旧コードが無い。**AJ blueprint 側にしか存在しない情報（frame番号・ロケータ名・アニメーション名）は、この仕様書に書き起こさない限り Claude から見えない。** 特に「§5 アニメーション一覧」は記載密度が実装品質に直結する。

---

## 1. 基本情報

| 項目 | 内容 |
|---|---|
| Uid | （例: 1005。mhdp_core側で未使用の番号） |
| 名前空間 | `mhdp_monster_<name>` |
| 表示名 / NameId | （例: `monster.<name>.name` → 実際の表示名） |
| モチーフ・概要 | （1-2行で。例: 「氷山を模した甲殻を持つ、遅いが範囲攻撃が強い水棲モンスター」） |
| サイズ・当たり判定の目安 | （体長、hitbox概算。判定箱サイズ提案の根拠として使う） |
| 移動属性 | 飛行/地上/水棲/その他（分岐ロジック・移動APIの選定に影響） |
| 参考にする既存モンスター | dino / ranposu / valk のうちどれに近い構造か（似た技があれば個別に後述の技一覧で明記） |

## 2. 部位構成

| PartId | 部位名 | 破壊対象か | 耐久値目安 | 弱点属性等 | 備考 |
|---|---|---|---|---|---|
| 0 | head | 例: あり | | | |
| 1 | body | 例: なし | | | |
| ... | | | | | |

- 破壊時に専用の怯みモーション/演出があるか（あれば§7で詳細記載）
- 切断（tail_cut のような特殊破壊）の有無

---

## 3. 状態・フェーズ

- 形態変化があるか（例: valk の 龍気形態⇔彗龍形態）。無ければ「単一形態」と明記。
- 各形態の名前・見た目上の違い・移行条件（HP閾値、行動回数、時間経過等）
- 怒り状態の有無・発動条件・解除条件
- 警戒（caution）/戦闘（battle）/待機（relax）の閾値（索敵範囲、視野角、見失い時間等。既存モンスターの値を流用してよいか明記）

---

## 4. 行動選択ロジック

- 距離帯分類: near/middle/far の区切り距離
- 距離帯・状態ごとの技の重み付け（大まかでよい。「近距離では噛みつきを出しやすい」等の意図が伝わればテキストで可）
- 大技解禁条件（クールタイム、フェーズ限定等）
- 威嚇/警戒行動の閾値

---

## 5. アニメーション一覧（★最重要・記載密度が実装品質に直結）

**技・状態ごとに1グループ**として、以下の情報を可能な限り埋める。埋められない項目（frame番号が未確定等）は「未定」と明記し、空欄のまま放置しない（空欄だと実装者が気付けない）。

### グループテンプレート
```
### <グループ名>（例: bite / tail_swipe_l）

- 対応するAJアニメーション名: <animated_java_<name>:<name>/animations/... の名前>
- 概要: <何をする技か、1行>
- 左右対称技か: <はい/いいえ。対称なら片方の記載で可、非対称ならL/R個別に記載>
- 移動: <無し / 固定tick移動(距離・方向) / 可変長移動（プレイヤー追従）>
- 軸合わせ: <無し / 開始frame・Tick・MaxRotation>
- 使用ロケータ: <ロケータ名一覧。pos_始まりかどうかも記載>
- フレーム構成（重要な frame 番号）:
  - 攻撃判定開始: frame __
  - 攻撃判定終了: frame __
  - （複数回ヒットする場合は判定区間ごとに列挙）
  - エフェクト発火点: frame __（VFX/サウンド等）
  - 終了/次アニメへの遷移: frame __
- 攻撃判定の形状目安: <球状距離なら半径、箱型なら想定サイズ。無ければ「類似技（dinoの◯◯等）を参考にしてよい」と明記>
- 使用VFX/オブジェクト: <既存流用可否、新規なら概要（§6参照）>
- 備考: <相殺可否、既存技との類似点、特殊な演出等>
```

- 全グループを事前に埋めきる必要はない。**Stage 5 の各グループ着手直前までに該当箇所が埋まっていればよい**が、実装順序が分かるよう一覧だけは先に列挙しておくと計画が立てやすい。
- frame番号は「未確定」でもよいが、その場合は実装時に必ずユーザー確認が発生する前提であることを認識しておく（実装が止まる/仮進行になる）。

---

## 6. VFX / 弾システム

- 新規に必要な VFX・弾があれば、技ごとに: 見た目の概要、ループ型か単発か、既存共有オブジェクト（`0016.ground_crack` 等モンスター非依存のもの）の流用可否
- 弾（射撃物）がある場合: 自己ダメージ判定の要否、速度・射程・着弾時の挙動（壁に当たったら消える等）
- 新規 ObjectId 帯の採番（Uid下4桁ベース。例: Uid1005 → `10050`〜）

---

## 7. 部位破壊・特殊状態の演出

- 部位破壊時のモデル変化（欠損表示等）の有無
- 麻痺・スタン・ダウン等の特殊状態の有無とその挙動（既存モンスターと同じ仕組みでよいか、固有の演出が要るか）

---

## 8. サウンド

- 使用するサウンドイベント一覧（未定の場合は「後日追加」と明記して進行をブロックしない）

---

## 9. 既存モンスターからの流用方針

- 「この技はdinoの◯◯とほぼ同じ構造でよい」のように、実装時に参考にできる既存グループを明記しておくと、実装者側の初回提案の精度が上がる（`new_monster_creation_guide.md` §2.3 の根拠付けに直結）。

---

## 記入者向け補足

- この仕様書は完成後に固定するものではなく、実装が進むにつれて Stage 5 の各グループ着手時に加筆・修正していく運用を想定している。
- 「未定」「後日確認」等の記載を歓迎する。**空欄で放置されるより、未定であることが明示されている方が実装側は安全に進められる。**
